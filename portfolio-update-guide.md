# Portfolio Update Guide (dirtcakestudio.com/cihangelerli)

How to update images and content on the portfolio page, how to publish the update, and how to add a second portfolio page (Phase 8).

Terms used in this guide:

- **Terminal**: the VS Code terminal (menu: Terminal > New Terminal), opened at the project root. The project root is the folder that contains `package.json`.
- **Master**: the finished image file you make yourself, at the largest size. The script makes the smaller copies from it.
- **Slug**: the short name in the page address. For this page it is `cihangelerli`. A second page gets its own slug.
- **Search in a file**: click inside the file, press **Ctrl+F** (Cmd+F on Mac). **Search in the whole project**: **Ctrl+Shift+F** (Cmd+Shift+F).

---

## 1. The routine (follow this every time)

| # | Do this | Where |
|---|---|---|
| 1 | Make your images as **WebP** at the right sizes (section 2) | Photoshop, Figma export, or squoosh.app |
| 2 | Put the files in the right folders (section 3) | `art-src/cihangelerli/thumbnails/` and `art-src/cihangelerli/gallery/` |
| 3 | Edit the image paths and texts in the data file (section 5) | `src/portfolio/cihangelerli.ts` |
| 4 | Run `npm run images` and wait for the **Done** line | Terminal |
| 5 | Run `npm run dev` and check the page at `http://localhost:3000/cihangelerli` (section 4, step 5) | Terminal + browser |
| 6 | Run `npm run build` and make sure it finishes without errors | Terminal |
| 7 | Commit and push to GitHub (section 4, step 7) | Terminal |
| 8 | Wait for Vercel to finish, then check the live page (section 4, step 8) | Browser |

How the image step is protected now:

- `npm run images` **checks every image first**. If anything is wrong, it prints what to fix and says **NOTHING WAS CHANGED**. Your last working images and manifest stay untouched.
- Hidden system files such as `.DS_Store` (created by macOS Finder) are ignored automatically.
- `npm run build` (and Vercel's build) **runs the images step by itself** before building, so a forgotten images step can no longer break the live site. You still run it yourself before testing locally, because `npm run dev` does not run it.

## 2. Image sizes

Both types must be **`.webp`** files.

| Image type | What to prepare | Notes |
|---|---|---|
| **Thumbnail** (the small picture you click) | **720 x 540 px**, exactly 4:3 | The script rejects other ratios and anything wider than 720 px. Aim for about 25-60 KB. |
| **Gallery image** (the big pictures after you click) | **960 px tall**, any width | Examples: 3:2 is 1440 x 960, 16:9 is 1707 x 960, a very wide pixel-art strip might be 2880 x 960. The script rejects anything taller than 960 px. Aim for under about 300-400 KB. |

How the sizes are used:

- The script copies your file untouched as the **largest** size.
- It generates smaller sizes from it for normal screens: thumbnails at 240 and 480 px wide, gallery images at 480 px tall.
- If you save a file as lossless WebP, the smaller sizes are lossless too. If lossy, they are lossy. The script reads this from the file, not from the name.
- Downscaled pixel art can look a little softer at the smaller size. This is normal.
- If a master is smaller than the recommended size, the script still accepts it and prints a warning. It will look soft on high-resolution screens.

The script prints `<-- heavy` next to a file if a thumbnail is over 60 KB or a gallery image is over 400 KB. Re-export it with lower quality if you see that.

All gallery images in one project are shown side by side at the same height, so mixed widths are fine.

### File names

- Only letters, numbers, hyphens, underscores and dots. **No spaces and no Turkish characters** (`ı`, `ş`, `ğ`, `ö`, `ü`, `ç`). The script rejects such names.
- End with `.webp`.
- Every name must be unique inside its folder.
- Suggested pattern: lowercase with hyphens. Thumbnail `dragon-city.webp`, gallery `dragon-city-01.webp`, `dragon-city-02.webp`.
- One file can be used by several projects. Just point to the same path in the data file.

## 3. Where files go

`art-src` is a folder at the **project root** (next to `package.json` and `src`). It is **not** inside `public` and **not** inside `src`.

```
project root/
  package.json
  art-src/                      <-- your masters
    cihangelerli/
      thumbnails/               <-- 720x540 .webp files
        dragon-city.webp
      gallery/                  <-- 960-tall .webp files
        dragon-city-01.webp
        dragon-city-02.webp
  public/
    cihangelerli/
      og-share.jpg              <-- WhatsApp/Twitter share image (section 6)

  src/
    portfolio/
      cihangelerli.ts           <-- the data file you edit

      image-manifest.json       <-- GENERATED by the script. Never edit by hand.
  scripts/
    build-images.mjs            <-- the image script
    postbuild-seo.mjs           <-- the share-card script
```

## 4. Step by step: updating the page

### Step 1. Prepare the images
Make the WebP files at the sizes in section 2 and name them as described.

### Step 2. Copy them into the folders
- Thumbnails into `art-src/cihangelerli/thumbnails/`
- Gallery images into `art-src/cihangelerli/gallery/`

### Step 3. Edit the data file
Open `src/portfolio/cihangelerli.ts` and follow section 5.

The path rule for every image `src:` line:

> Take the file's location **inside `art-src`**. Do not write `art-src/` at the start. Do not put a `/` at the start.

| File location | Value to write in the data file |
|---|---|
| `art-src/cihangelerli/thumbnails/dragon-city.webp` | `"cihangelerli/thumbnails/dragon-city.webp"` |
| `art-src/cihangelerli/gallery/dragon-city-01.webp` | `"cihangelerli/gallery/dragon-city-01.webp"` |

### Step 4. Generate the final images
In the terminal:

```bash
npm run images
```

Success looks like one line per file, then a **Done** line:

```
cihangelerli/thumbnails/dragon-city: 240, 480, 720, master 38 KB
cihangelerli/gallery/dragon-city-01: 480, 960, master 214 KB

Done: 24 images (12 thumbnails, 12 gallery) in 1 page(s). Manifest updated.
```

If something is wrong you see this instead, and **nothing is changed**:

```
Fix these files and run again:
  - art-src/cihangelerli/thumbnails/x.webp: thumbnails must be 4:3 (found 800x600) ...

NOTHING WAS CHANGED. Your previous images and manifest are untouched.
```

Fix every file in the list and run the command again.

| Message | Fix |
|---|---|
| `thumbnails must be 4:3` | Re-export that thumbnail at exactly 720 x 540. |
| `width must be at most 720px` | The thumbnail is too wide. Re-export at 720 x 540. |
| `height must be at most 960px` | The gallery image is too tall. Re-export at 960 px tall. |
| `not a .webp file` | Convert the file to WebP, or remove it from the folder. |
| `file name may only use ...` | Rename the file: no spaces, no special or Turkish characters. |
| `cannot be read as an image` | The file is damaged. Export it again. |
| `folders inside ... are not supported` | Remove the subfolder, or move its files directly into `thumbnails` or `gallery`. |

A successful run creates or replaces `public/cihangelerli/img/` and `src/portfolio/image-manifest.json`. That is expected.

### Step 5. Check it locally
```bash
npm run dev
```
Open `http://localhost:3000/cihangelerli`.

Check:
- Thumbnails look sharp, with no broken-image icons.
- Click each project you changed. The gallery images appear and you can scroll sideways.
- Press **F12**, open the **Console** tab. It should show no red errors. In the **Network** tab, nothing should be red (404).
- Texts, links and the tab title are correct.

Stop the server with **Ctrl+C**.

### Step 6. Build
```bash
npm run build
```
This first runs the images step by itself (you will see the **Done** line), then builds the site. It must finish with **no errors**. Near the end you should see:

```
wrote dist/cihangelerli/index.html
```

If you do not see that line, the share-card step is missing from the `"build"` line in `package.json`. It should contain `node scripts/postbuild-seo.mjs`.

### Step 7. Commit and push
```bash
git status
```
You should see changed or new files in these places:
- `art-src/cihangelerli/...` (your masters)
- `public/cihangelerli/img/...` (generated images)
- `src/portfolio/image-manifest.json`
- `src/portfolio/cihangelerli.ts`

Commit the generated files too. Vercel regenerates them anyway, but having them in GitHub means `npm run dev` works right after cloning on another computer.

```bash
git add .
git commit -m "Update portfolio images and content"
git push
```

### Step 8. Check the live site
1. Open the Vercel dashboard, then your project, then **Deployments**. Wait until the newest one says **Ready** (usually 1-2 minutes). If it says **Error**, open it, read the Build Logs, and look at the images step output (see section 8).
2. Open `https://www.dirtcakestudio.com/cihangelerli` and hard-refresh with **Ctrl+Shift+R** (Cmd+Shift+R on Mac).
3. Click through the projects you changed.
4. If you changed the share card or title, see section 6.

## 5. Editing the data file (`src/portfolio/cihangelerli.ts`)

### 5.1 Map of the file
Use **Ctrl+F** to jump to these words. Line numbers change over time, so search instead of scrolling.

| Search for | What it is |
|---|---|
| `identity:` | Your name, roles and intro text |
| `about:` | Experience, location, education, languages, skills, CV link |
| `onlinePresence:` | Social links with their icons |
| `categories:` | All portfolio categories and projects (this is the big part) |
| `ui:` | Small labels, the "get in touch" link and the footer copyright text |
| `seo,` | Near the bottom. The tab title and share image come from `cihangelerli.seo.json` |

Your categories are: Illustration (`id: "illustration"`), Isometric Game Art (`id: "isometric-game-art"`), a third one whose projects are called `game-backgrounds-project-N`, and UI Design (`id: "ui-design"`).

**Find a specific project:** press Ctrl+F and type its id, for example `ui-design-project-3`.

**Find placeholders that are not replaced yet:** search for `/cihangelerli/thumbnail-` and then for `/cihangelerli/gallery-`. Each search shows "x of N" in the search box. **When both show "No results", every placeholder is replaced.**

### 5.2 Anatomy of one project

```ts
{
  id: "illustration-project-1",          // must be unique, never reused
  name: "Dragon City",                   // optional: title shown after clicking
  subtitle: "Client or game name",       // optional
  link: { label: "Link", url: "https://example.com/" },   // optional
  description:
    "Text about the project.",           // optional
  thumbnail: {
    src: "cihangelerli/thumbnails/dragon-city.webp",
    alt: "Short description of what the thumbnail shows",
  },
  gallery: [
    {
      src: "cihangelerli/gallery/dragon-city-01.webp",
      alt: "Short description of this image",
    },
    {
      src: "cihangelerli/gallery/dragon-city-02.webp",
      alt: "Short description of this image",
    },
  ],
},
```

Rules for the optional lines:
- **`name`**: if you leave it out, the page shows "Illustration Project 1" (category name plus a number). Placeholders without a `name` show that.
- **`subtitle`, `description`**: delete the whole line, or leave `""`, to hide it.
- **`link`**: shown only if both `label` and `url` have text. Delete the `link:` line to hide it. Links starting with `http` open in a new tab.
- **`thumbnail` and `gallery`** are required. A project needs **at least one gallery image**. Never leave `gallery: []` empty.

### 5.3 Recipes

**A. Replace a placeholder thumbnail with a real one**

1. Search the project id, for example `illustration-project-1`.
2. Under it, find `thumbnail:`.
3. Change the `src` line and the `alt` line.

Before:
```ts
thumbnail: {
  src: "/cihangelerli/thumbnail-green-isometric.png",
  alt: "Colorful isometric game scene with green paths and small structures",
},
```
After:
```ts
thumbnail: {
  src: "cihangelerli/thumbnails/dragon-city.webp",
  alt: "Isometric dragon city scene with a harbor and market",
},
```

**B. Replace the gallery images of a project**

Inside that project's `gallery: [ ... ]`, change each `src:` and `alt:` the same way, pointing to `cihangelerli/gallery/<file>.webp`. The images appear in the order of the list, and the first one loads first, so put the best one first.

**C. Add a gallery image to a project**

Copy one whole `{ src: ..., alt: ... },` block inside `gallery: [ ... ]`, paste it below another block, and change `src` and `alt`. Keep the comma at the end of every block.

**D. Remove a gallery image**

Delete the whole `{ ... },` block, from the opening `{` to the closing `},`. Keep at least one image.

**E. Add a new project to a category**

1. Search the category (for example `id: "illustration"`) and find its `projects: [` list.
2. Select one **complete** project block, from `{` at the line with `id:` down to the closing `},`.
3. Copy it and paste it directly after another project's closing `},` inside the same list.
4. Change the `id` to something new and unique, for example `illustration-project-5`.
5. Fill in `name`, texts, `thumbnail` and `gallery` as in 5.2.

The new thumbnail appears at the end of that category's row of thumbnails.

**F. Remove a project**

Delete the whole block from its `{` to its closing `},`. Then delete its images from `art-src` if you do not need them. The next `npm run images` removes their generated files automatically.

**G. Add a new category**

1. Find the end of the last category, just before the line `] satisfies PortfolioCategory[],`.
2. Copy a whole category block (it starts with `{` and `id: "ui-design",` for example, and ends with `},`) and paste it after the last category's `},`.
3. Change `id`, `label` and `description`, and replace its projects (at least one).

**H. Change the footer year**

Search `footerCopyright` and edit the year.

**I. Change the CV link**

Search `cvUrl`. Either use a Google Doc link set to "Anyone with the link: Viewer", or put a PDF at `public/cihangelerli/cv.pdf` and write `cvUrl: "/cihangelerli/cv.pdf",`.

**J. Change a social link**

Search `onlinePresence`. Edit `label`, `description` and `url`. The `icon` must point to a file that exists in `public/cihangelerli/`, written as `/cihangelerli/icon-name.svg` (with the leading slash).

### 5.4 Typing mistakes that break the page
- Every property and every `{ ... }` block in a list ends with a **comma**.
- Use straight quotes `"`, not curly quotes.
- Every `{` has a closing `}`, and every `[` has a closing `]`.
- VS Code underlines mistakes in red. Hover over the red line to read the problem. Do not run the build until the red lines are gone.

### 5.5 One-time cleanup of the old placeholder files
Do this only when the searches in 5.1 for `/cihangelerli/thumbnail-` and `/cihangelerli/gallery-` both show "No results".

1. Press Ctrl+Shift+F and search the whole project for `gallery-pixel-city` and `thumbnail-green-isometric`. Nothing should match.
2. In `public/cihangelerli/`, delete the old placeholder files: everything named `thumbnail-*.png` and `gallery-*.png`.
3. **Keep** the `icon-*.svg` files, `og-share.jpg` and the `img` folder.
4. Run `npm run build`, then commit and push.

## 6. Changing the tab title or the share image

The tab title, the page description and the share image path all live in one file: `src/portfolio/cihangelerli.seo.json`.

```json
{
  "canonicalPath": "/cihangelerli",
  "title": "Cihan Gelerli - Freelance Game Artist",
  "description": "I'm a 2D and 3D generalist, with a focus on illustration, UI design and isometric game art in recent years.",
  "openGraphImage": "/cihangelerli/og-share.jpg"
}
```

**To change the share image (the picture WhatsApp and Twitter show):**
1. Make a **1200 x 630 px JPG**, quality 75-85, **under 300 KB**. Keep the important content in the middle square (about 630 x 630 px).
2. Save it as `public/cihangelerli/og-share.jpg`, replacing the old one.
3. Run `npm run build`, then commit and push.
4. Test the preview with a changed link so the old one is not cached: `https://www.dirtcakestudio.com/cihangelerli?v=2` (use `?v=3`, `?v=4` for each retry). Facebook's Sharing Debugger (use "Scrape Again") and LinkedIn Post Inspector also work.

**To change the title or description:** edit the text in the JSON file, then build, commit and push.

**To check what crawlers see:** open the live page, right-click, **View Page Source** (not Inspect), press Ctrl+F and search for `og:image`.

## 7. Phase 8: adding a second portfolio page (for example, for your girlfriend)

Do this after your own page is finished. Pick a slug: lowercase, no spaces, URL-safe. Below it is written `her-slug`. Replace it with the real slug everywhere, and replace `HER_PORTFOLIO` and `HerPage` with names you like (for example `JANE_PORTFOLIO` and `Jane`).

Her page uses the same layout and styling as yours. Only the content differs. The image script handles every folder inside `art-src` automatically.

| # | File or folder | What to do |
|---|---|---|
| 1 | `art-src/her-slug/thumbnails/` and `art-src/her-slug/gallery/` | Create both folders. Her images go here (same sizes as section 2). |
| 2 | `public/her-slug/` | Create this folder. Put her `og-share.jpg` (1200 x 630) and her icon SVG files here. You can copy `icon-instagram.svg` etc. from `public/cihangelerli/`. |
| 3 | `src/portfolio/her-slug.ts` (new file) | Copy `cihangelerli.ts` to this name. Inside it: rename `CIHAN_GELERLI_PORTFOLIO` to `HER_PORTFOLIO`. At the very bottom, rename `export type CihanGelerliPortfolio = typeof CIHAN_GELERLI_PORTFOLIO;` to match, or delete that line. Change the import line `import seo from "./cihangelerli.seo.json";` to `import seo from "./her-slug.seo.json";`. |
| 4 | Inside `her-slug.ts` | Replace identity, about, social links, categories, projects, footer text and the get-in-touch link with her content. Every image `src` starts with `her-slug/` (example: `"her-slug/gallery/photo-01.webp"`). Remove your own social links (glitchbooth, dirtcake). Every `icon` is `/her-slug/icon-name.svg`. Each category needs at least one project, and each project needs at least one gallery image. |
| 5 | `src/portfolio/her-slug.seo.json` (new file) | Copy `cihangelerli.seo.json`. Set `canonicalPath` to `"/her-slug"`, `openGraphImage` to `"/her-slug/og-share.jpg"`, and write her `title` and `description`. |
| 6 | `src/pages/HerPage.tsx` (new file) | Paste the code below. |
| 7 | The file that registers your routes | Press Ctrl+Shift+F and search `CihanGelerli`. Find the import and the route for your page. Copy both for hers, in the same style (including lazy loading if that is how yours is written). Use `HerPage` and the path `/her-slug`. |
| 8 | `vercel.json` (project root) | In the image caching rule, change `"/(cihangelerli)/img/(.*)"` to `"/(cihangelerli|her-slug)/img/(.*)"`. |
| 9 | Terminal | Run `npm run images`, then `npm run dev` and open `http://localhost:3000/her-slug` to check. Then `npm run build` (it prints a `wrote dist/her-slug/index.html` line), then commit and push as in section 4, steps 7-8. |

`src/pages/HerPage.tsx`:

```tsx
import PortfolioPage from "./PortfolioPage";
import { HER_PORTFOLIO } from "../portfolio/her-slug";

export default function HerPage() {
  return <PortfolioPage portfolio={HER_PORTFOLIO} />;
}
```

After the first deploy of her page, check its share card like section 6, using her URL.

Later updates to her page follow sections 1-6 exactly, with `her-slug` in place of `cihangelerli` and `her-slug.ts` in place of `cihangelerli.ts`.

## 8. Troubleshooting

| What you see | Most likely cause | Fix |
|---|---|---|
| `NOTHING WAS CHANGED` after `npm run images` | At least one image or file name is invalid | Read the list above that line, fix each file, run again. Your last working version is still in place. |
| A broken-image icon on the page | Typo in the `src` path, the file is not in `art-src`, or you did not run `npm run images` | Compare the `src` with the table in section 4, step 3. Check the file exists in the right `art-src` folder. Run `npm run images`. |
| One image gives a 404 in the Network tab | The manifest and the generated files are out of sync | Run `npm run images` until it prints **Done**, then restart `npm run dev`. |
| Live site still shows old images | Vercel is still building, or the browser cache | Check Vercel Deployments for "Ready". Hard-refresh with Ctrl+Shift+R. |
| Vercel deployment says **Error** | The build failed, usually at the images step | Open the deployment, read the Build Logs. If it lists image files, fix them and push again. If it mentions `sharp`, copy the log and ask for help. The previous version of the site stays live in the meantime. |
| `npm run images` says `Cannot find package 'sharp'` | Packages are not installed on this computer | Run `npm install`, then run it again. |
| `npm run images` says `art-src/ folder not found` or `No images found` | Wrong folder location or names | The folders must be exactly `art-src/cihangelerli/thumbnails` and `art-src/cihangelerli/gallery`, at the project root. |
| Build error `Cannot find module './image-manifest.json'` | The manifest does not exist yet | Run `npm run images`. |
| Build or page error in `cihangelerli.ts` | A missing comma, quote or bracket | Look for red underlines in the file (section 5.4). |
| A gallery or page jumps while loading | The image is not in the manifest (the `src` does not match a generated file) | Fix the `src` path and run `npm run images`. |
| Image is blurry on a phone | The master is smaller than the recommended size | Re-export at 720 x 540 (thumbnail) or 960 px tall (gallery). |
| Tab title is wrong | `cihangelerli.seo.json` was not updated, or the new build is not live yet | Edit the JSON, build, commit, push. Hard-refresh. |
| `wrote dist/cihangelerli/index.html` is missing from the build output | The `"build"` script in `package.json` does not include `node scripts/postbuild-seo.mjs` | Add it back. |
| WhatsApp/Twitter shows an old preview | They cache previews | Share the link with `?v=2`, `?v=3` added. |

## 9. Other things to remember

- **Back up masters.** Your files in `art-src` are your originals at full quality. They are committed to GitHub, so they are backed up there too.
- **Renaming an image:** change the file name in `art-src`, change the `src` in the data file, then run `npm run images`. Old generated files are removed automatically on each run.
- **Replacing an image with the same file name:** just overwrite it in `art-src` and run `npm run images`. The generated file names change automatically, so visitors get the new image.
- **The `prebuild` line in `package.json`** is what runs the image step during `npm run build` and on Vercel. Do not delete it. The `scripts` part should contain `"images": "node scripts/build-images.mjs"` and `"prebuild": "npm run images"`.
- **Vercel build command:** in the Vercel dashboard, Project > Settings > Build and Deployment, the Build Command Override should be **off**, or set to `npm run build`. If Vercel runs `vite build` directly, the `prebuild` step is skipped and the share-card step too.
- **`.gitignore`** should contain the line `.images-tmp` (a temporary folder the script uses and deletes itself).
- **New computer:** after cloning the repo, run `npm install` once before `npm run images` or `npm run dev`.
- **Sitemap:** if dirtcakestudio.com has a `sitemap.xml`, add `https://www.dirtcakestudio.com/cihangelerli` to it (and her page later).
- **After the real images are in:** run Lighthouse (Chrome DevTools > Lighthouse > Mobile) on the live page. Layout shift should be near 0 and the first load should be small.

### Things to confirm once

These were not visible to me when I wrote this guide, so check them once and fix this document if they differ:
- Whether `package.json` has a `preview` script (`npm run preview` tests the built site locally).
- The exact id of the third category in the data file (I only saw its projects named `game-backgrounds-project-N`).

## 10. Command cheat sheet

| Command | What it does |
|---|---|
| `npm install` | Installs packages (only needed once per computer, or after `package.json` changes) |
| `npm run images` | Checks all images in `art-src`, makes the smaller sizes, updates `image-manifest.json`. Changes nothing if anything is wrong |
| `npm run dev` | Starts the page locally at `http://localhost:3000` for testing (Ctrl+C stops it). Does not run the image step |
| `npm run build` | Runs the image step, builds the real site, and creates the share-card pages. Must finish without errors |
| `git status` | Shows what changed |
| `git add .` | Selects all changes for the commit |
| `git commit -m "message"` | Saves the changes with a message |
| `git push` | Sends the commit to GitHub, which triggers Vercel to deploy |
